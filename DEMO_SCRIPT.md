# Demo Script: Trao AI Interview Prep Kit

**Estimated Duration**: 5 - 7 minutes

| Timestamp | Screen / Action | Script / Voiceover | Expected Result |
| :--- | :--- | :--- | :--- |
| **0:00 - 0:30** | **Login/Auth**: Open browser to `localhost:3000`. Show login screen and log in. | "Welcome to the Trao Interview Prep Kit. I'll start by logging in. The system uses secure JWT authentication, so every user's kits and progress are strictly isolated." | User successfully authenticates and is routed to the Dashboard. |
| **0:30 - 1:15** | **Dashboard & Kit Generation**: Click "New Kit". Paste a standard Job Description. Enter a company URL (e.g. Stripe, Vercel). Select '5' interview days. | "Here is the dashboard. I'm going to generate a new kit. I'm pasting in a standard React Developer Job Description, providing the company URL for context research, and choosing a 5-day prep schedule. Let's hit generate." | Loading state appears indicating research, extraction, and drafting progress. |
| **1:15 - 2:00** | **Review Generation Results**: Once generation completes, open the Builder view. Show Company Brief, Role Requirements. | "The generation is complete. The system dynamically crawled the homepage and researched public interview processes. You can see a customized company brief and the specific technical and behavioural requirements mathematically extracted from the JD." | Company brief, requirements array with MUST/NICE tags, and source metadata are displayed. |
| **2:00 - 2:30** | **Question Bank**: Scroll down to the Questions section. Show the mapped requirement IDs. | "Here is the question bank. Notice how every question strictly references one or more extracted requirement IDs. It also indicates the category and difficulty level." | Questions display properly mapped `requirement_ids`. |
| **2:30 - 3:15** | **Builder Editing**: Edit a question's text. Click "Add Question" and create a dummy question. Drag to reorder a question. Delete a question. | "We can actively curate this kit. I'll edit this question slightly. I'll also add my own custom question, reorder them, and delete one I don't like." | UI updates instantly. Edits reflect locally. |
| **3:15 - 3:45** | **Regeneration**: Click "Regenerate Questions". | "Now, what if we want fresh AI questions but want to keep our manual edits? I'll click regenerate on this section. Because the backend explicitly tracks the 'origin' of each question, our manual additions and edits survive the regeneration unharmed." | Loading state. UI updates. Edited and manually added questions remain untouched; AI questions are refreshed. |
| **3:45 - 4:15** | **Practice Mode & Flashcards**: Click "Practice Mode". Flip a flashcard. Select a confidence score (e.g., '4'). | "Moving to Practice Mode. The system generated flashcards covering the required concepts. After reviewing, I'll rate my confidence a 4 out of 4." | Flashcard flips. Confidence state is visibly updated. |
| **4:15 - 4:45** | **Persistence**: Refresh the page / navigate away and back. | "Crucially, this confidence score persists to the MongoDB backend. If I refresh the page, the cards sort dynamically based on my historical confidence scores." | Page reloads. The card previously rated '4' persists its state and position. |
| **4:45 - 5:15** | **Study Schedule**: Navigate to the Schedule view. | "The system also produced a deterministic 5-day schedule. Durations are calculated in whole integer minutes, and the logic guarantees that every 'MUST' requirement is covered across the study days." | Schedule UI displays 5 days with correctly partitioned questions/flashcards. |
| **5:15 - 5:45** | **Batch / Multi-Role**: Go back to Dashboard. Upload a CSV/JSON containing 3 different roles. | "Finally, the assignment asked for multi-role uploads. I'll upload this JSON file containing three separate roles. The backend processes these concurrently, guarded by a global semaphore to respect rate limits, and isolates failures so one bad row won't break the entire batch." | Batch upload succeeds. 3 new kits populate in the dashboard. |
| **5:45 - 6:00** | **Wrap Up**: Show terminal output briefly if desired. | "Behind the scenes, we use deterministic Zod schemas, strict coverage retry logic, and exponential backoff to handle Gemini 503s. Thank you." | End demo. |
